流程分析 · 记忆操作流转与问题节点定位
流程分析把 Agent 落库的记忆事件还原为「turn 级流程」：一个 turn 是一轮交互内的记忆操作序列，每个操作归一化为节点（read/write/update/expire × prompt/session/skill/provider，如 read@session=会话记忆检索），相同序列归并为流程变体并统计频次，据此画出转移图并自动定位出问题的节点。三栏这样用：① 左栏「流程（按频次）」列出每种变体的出现次数、占比与 token 消耗，含循环/坏味道标记，点击条目会在中栏高亮对应路径；② 中栏「转移图」节点编号即流向顺序（1 为起点，▶ 起点、⏹ 终点），边宽 = 转移频次，节点色 = 操作类型（青=读取/绿=写入/紫=更新/红=遗忘），描边 = 健康度（红=问题/橙=预警/深色=正常），划过节点点亮其邻接路径、点击可钉住，支持拖拽缩放；③ 右栏「问题节点」卡片列出命中信号的节点（S1 烧钱/S2 慢/S3 循环参与/S7 失败率），点击卡片会在图上定位该节点并弹出详情滑块，展示是哪几个 turn 出的问题、证据与操作上下文。使用时先在顶部选择 Agent，可再按 Session（一个 Session 含多个 turn）与时间窗口过滤。为什么监控它：转移图把记忆事件按「操作 × 层级」聚合成状态机，看 Agent 在记忆层「怎么走」——红色自环边就是循环。风险信号 S3：同一状态反复转移（READ→READ→READ）= Agent 在原地打转，token 与延迟空烧、任务不会前进。解决什么问题：Agent 卡死/死循环靠肉眼看日志很难发现，转移图 + 自环循环计数让「打转」显形，据此可触发循环熔断或提示用户接管。

参数 / 枚举 / Harness 场景说明
  • operation：READ 读取 / WRITE 写入 / UPDATE 更新 / EXPIRE 过期遗忘
  • layer：prompt 提示词 / session 会话汇总(turn) / skill 技能调用 / provider 外部工具·API
  • timestamp：严格格式 yyyy-MM-dd HH:mm:ss（如 2026-08-22 11:25:50），按亚洲上海时区解析，非此格式该行将报错跳过
  • Turn 场景（metadata）：turn_message_id 同轮对话标识、turn_user 用户问题、turn_actions 操作步骤、turn_outcome 总结产出
  • Action 子步骤（metadata）：action_idx 第几步、action_full 该步完整内容；用同一 turn_message_id 关联即展示完整操作步骤
  • Skill 场景（metadata）：skill_name 技能名（配 layer=skill）、skill_status 结果 success/failed/running、span_id/trace_id/parent_span_id 组成调用链路
  • Excel 模板含「参数说明·Harness 场景」清单页，字段与枚举齐全可照抄
